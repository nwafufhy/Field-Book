# Field Book 开源许可证分析

> 分析日期：2026-05-14

## 当前状态

| 位置 | 许可证 | 状态 |
|------|--------|------|
| 仓库根目录 | 无 LICENSE 文件 | **All Rights Reserved**（GitHub 默认） |
| `fieldbook-android/` | [GNU GPL v2](https://www.gnu.org/licenses/old-licenses/gpl-2.0.html) | 已声明 |
| `brapi-light/` | 无 | **权利状态不明** |

## GPL v2 核心条款解读

### 允许

- 自由使用、修改、分发
- 对分发行为收费
- 提供有偿担保服务
- 内部使用无需公开代码

### 限制

| 条款 | 内容 | 影响 |
|------|------|------|
| **Copyleft（第 2(b) 条）** | 包含或衍生自该程序的代码，必须整体以 GPL v2 发布 | 修改版必须同样开源 |
| **源代码公开（第 3 条）** | 分发二进制时必须提供完整源代码 | 不能只给 APK 不给源码 |
| **禁止额外限制（第 6 条）** | 不得对下游接收者施加额外约束 | 不能限制商用、安装数量等 |
| **禁止闭源化** | 许可证末尾明确禁止将程序并入专有软件 | 不能嵌入闭源商业产品 |

## 对推广和商业化的影响

### 高风险

1. **GPL 传染性**：任何基于 fieldbook-android 的修改版本，包括 UI 改造、功能增强，**分发时必须整体 GPL 开源**
2. **企业接受度低**：许多企业客户排斥 GPL 软件，担心自有代码被"传染"
3. **商业化路径受限**：无法做成闭源商业 App，竞争壁垒只能靠服务质量而非代码

### 可操作空间

- **SaaS 免责**：GPL v2 不触发网络分发条款（AGPL 才覆盖），brapi-light 作为后端服务无强制开源压力
- **双许可证**：版权持有人可同时以商业许可证单独授权给付费客户
- **内部工具**：仅供内部使用不分发时，无需公开代码

## brapi-light 许可证空白

`pyproject.toml` 中未声明 `license` 字段，目录下无 LICENSE 文件。法律上默认保留所有权利，任何第三方无法合法使用、修改或分发。建议尽快明确许可证。

## 如果目标是宽松推广

当前 GPL v2 对推广有显著阻力。如果想放宽限制，可选方案：

| 方案 | 二次开发 | 闭源商业化 | 专利保护 | 适用场景 |
|------|----------|------------|----------|----------|
| **MIT** | 不强制开源 | 允许 | 无 | 最大化推广 |
| **Apache 2.0** | 不强制开源 | 允许 | 有 | 含专利权保护 |
| **LGPL** | 库级 copyleft | 允许链接 | 无 | 库/框架 |
| **GPL v3** | 强制开源 | 禁止 | 有 | 保持 copyleft |
| **AGPL v3** | 强制开源 | 禁止（含 SaaS） | 有 | 最强 copyleft |

## 建议

1. **短期**：仓库根目录添加明确的 LICENSE 文件
2. **短期**：为 brapi-light 选择并声明许可证
3. **中期**：评估当前 GPL v2 是否与项目推广目标一致，必要时更换许可证（需征得所有贡献者同意）
